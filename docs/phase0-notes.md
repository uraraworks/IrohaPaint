## WebPaint98 からの流用と、あえて流用しなかったもの

流用したのは **プロジェクトの型**：Vite + TypeScript + vitest、`base: "./"`、GitHub Pages
ワークフロー、IndexedDB の扱い方（DB を用途ごとに分ける・壊れた保存データでは復元しない）。

流用しなかったのは **入力の設計思想**。WebPaint98 は「マウス前提のデスクトップ UI を指で操る」
ための翻訳層（長押しでドラッグ開始など）を持つが、本アプリは **タッチが母語でマウスが後追い**
なので向きが逆になる。したがって：

- 長押し待ちを挟まない。指が触れた瞬間に線が出る（受け入れ条件 1 の生命線）
- ホバー・右クリックに機能を置かない。機能は必ず可視のボタンに置く
- 描画エンジン自体（PC-98 の VRAM プレーン・16 色）は前提が違うため流用しない

## 実装上の要点

- **undo はパッチ方式**（`src/core/undoStack.ts`）。キャンバスが 1748×1181 なので全面
  スナップショットは 1 枚 8MB 強。変化した矩形の「変更前」だけを持ち、合計バイト数で
  間引く。変更範囲は描き終わるまで確定しないため、1 手前の状態を映した控えキャンバスを
  1 枚だけ持ち、描き終わってからその矩形を控えから拾う（`src/core/surface.ts`）
- **ピンチは CSS transform**（`src/core/viewport.ts`）。画面→キャンバス座標の変換は
  `getBoundingClientRect()` が変換後の矩形を返すので、入力側は拡大を知らなくてよい
- **2 本目の指が触れたら描きかけを捨てる**。写真アプリの感覚でピンチした子に意図しない線を残さない
- **効果音は Web Audio で合成**。音声ファイルを置かないので読み込み待ちゼロ。初回タップまで
  AudioContext を作らない（自動再生制限）

## 下バー vs 左バー

既定は下バー（ibisPaint / MediBang / CSP mobile と同じ）。誤タッチ対策として：

- `env(safe-area-inset-bottom)` で OS のジェスチャ帯（ホームインジケータ／ナビバー）を避ける
- ボタンは `click`（押して離す）でのみ発火。描画中に指が滑り込んでも誤爆しない
- パネルはツールバーに重ならない位置に出す（パネル越しにボタンを押させない）

学童検証で誤タッチが観測されたら、`index.html` の `class="app bar-bottom"` を
`bar-left` に変えるだけで左サイドへ倒せる（CSS 側は対応済み。左バー時はボタンが縦積みになる）。

## 作品カタログ

一覧の見た目は **ファミレスのメニュー方式**：写真（サムネイル）が主役、文字は一言、カードは全部同じ形。
文字を読まなくても絵で選べることを最優先にしている。Phase 1 の「道具カタログ」も同じ骨格を使える
（カード＝絵＋一言＋1 アクション、という形は道具カタログの「つかってみる／やめる」にそのまま乗る）。

- 文言は道具ボタンと同じく **漢字＋総ルビ（L2）**、ボタンはすべて **アイコン＋文言** の同じ形。
  日付も `LabelPart[]`（「8月（がつ）29日（にち）」）で返しており、L3（ふりがなオフ）へ切り替えたときに
  日付だけ取り残されない
- 一覧では **サムネイル（幅 360px の PNG）** を保存のたびに一緒に作って持つ。
  原寸（1748×1181）を並べると読み込みだけで数十 MB 動くため
- 「あたらしく かく」を押した時点で空の作品を 1 枚作って開く。描く前に閉じた子の絵が迷子にならない
- 「すてる」はフラグを立てるだけ（`setDeleted`）。ゴミばこから「とりもどす」でいつでも復活。
  ゴミばこの中の絵は開けない（まず「とりもどす」を通す＝取り違えを起こさせない）
- いま開いている作品を捨てたら、残っているいちばん新しい絵へ移る。1 枚も無ければ白紙を用意する
  （描く場所が無い状態を作らない）
- 起動時は前回ひらいていた作品の続きから（`currentWorkId`）。無ければいちばん新しい絵

## アイロンビーズ / ドット絵モード

下敷きのサブメニューで「ビーズ」を選ぶと、マス目にしか置けないモードになる。1 マス = 1 ビーズで、描いた図案を見ながら実物のアイロンビーズを
並べられる（＝画面の中だけで終わらない出口。企画書§4.5「出口も育つ」に載る）。

- マス数は **58×39**。1748×1181 をこの数で割ると 1 マス ≒ 30px でほぼ正方形になり、
  実物のペグボード（29×29）がちょうど 2 枚ぶん入る
- **太さもペン先も持たない**（1 マス = 1 ビーズなので太さの概念が無い）。
  モード中は「描く」「消す」を押してもパネルを出さない
- 速く動かすとイベントが飛ぶので、前の点との間を補間して **通過したマスを埋める**
- 同じマスは 1 ストロークにつき 1 回だけ塗る（塗り重ねで色が濁らないように）
- 下敷き自体がビーズのマス目なので、マス目が消えることはない
- 細かく描き込むときはピンチで拡大する（一人モードなら拡大が使える）

ビーズの見た目と塗り:

- ビーズは **穴あきの円**で描く。四角で埋めるより出来上がりに近く、図案として数えやすい。
  穴はアイロンで溶けると縮むので、実物の穴より小さめ（円の 17%）にして仕上がりに寄せた
- 色は **実物の基本セットに寄せた 24 色**に差し替わる（`BEAD_COLORS`）。クレヨン 12 色のままだと
  **手元に無い色で描いてしまい再現できない**。ビーズへ入った時点で、選んでいた色は
  いちばん近いビーズ色へ寄せる
- 塗りつぶしは **マス単位**で広げる（`fillCells`）。円は隙間があるので、画素をたどる
  塗りつぶしだと背景へ漏れる
- マスの色を見るとき **中心を見てはいけない**。穴＝透明なので「置いてあるのに空」と判定してしまう。
  塗りつぶしが全面へ漏れる／スポイトが紙の色を吸う、という形で両方とも実際に出た。
  中心を外した輪の上を数点みる（`beadProbePoints`）。スポイトは何も無いマスなら
  色を変えない（紙の色を吸って「白いビーズ」になるのを防ぐ）

残っている検討事項:

- **マス目付きの印刷出力**（見ながら並べるための図案。PNG に方眼は入らないので別途必要）
- ビーズの個数表（色ごとに何個要るか）があると、作る前に足りるか分かる

## 右クリック = スポイト

マウスの右クリックで、その場の色を吸う（**道具は切り替えない**。描いている途中に色だけ
変えたいという使い方のため）。ツールバーの「スポイト」を押したときだけは、
吸ったあと自動で「描く」に戻す（吸って描く、までで 1 動作）。

タッチには右クリックが無い。2 本指を当てる案は採らない — **どのマスの色を吸うのかが
指で隠れて見えない**ため。タッチでは素直に「スポイト」を押してもらう。

## 全画面ボタン

WebNP2 と同じ作法（`src/core/fullscreen.ts`）:

- 対象は **ページ全体（`documentElement`）**。特定の要素を全画面にすると、その部分木の外にある
  ツールバーやパネルが一切描画されない
- iPhone の WebKit は `<video>` 以外の全画面に対応しておらず、メソッド自体が生えていない
  （iPad は webkit 版を持つ。iOS 版 Chrome も中身は WebKit なので同じ）。
  押しても無反応なボタンは置かないので、**使えない環境ではボタンごと出さない**。
  iPhone はホーム画面に追加すれば全画面で開ける
- Safari は接頭辞付き（`webkit*`）しか無い版があるため両方を見る
- Esc やシステム側の操作で抜けたときも見た目を合わせる（`fullscreenchange` を購読）

## 拡大しているときの移動

タッチは 2 本指で完結する（ピンチ＝拡大 / ドラッグ＝移動）。PC には指が 2 本無いので、
ブラウザや Figma / Photoshop と同じ割り当てにした:

| 操作 | 動き |
|---|---|
| ホイール | 上下に移動 |
| Shift + ホイール | 左右に移動 |
| Ctrl（⌘）+ ホイール | 拡大・縮小 |

トラックパッドのピンチは `ctrlKey` 付きのホイールとして届くので、この割り当てだと
「2 本指でこする＝移動、つまむ＝拡大」が何もしなくても一致する。

拡大中だけ **「ぜんぶ」ボタン**（等倍に戻す）が出る。拡大したまま迷子になるのを防ぐ安全弁で、
子どもが自力で元に戻せる出口をひとつ用意しておく。

## 「みんなで描く」モード

同じ端末に触れた指が **全部それぞれ線になる**（`pointerId` ごとに独立したストローク）。
学童の大きめタブレットで 2〜4 人が 1 枚に描く用。サーバーは要らない。

一人のときと道具立てを切り分ける:

| | 一人 | みんな |
|---|---|---|
| ピンチ拡大 | あり（描き込むため） | なし（一発描きに割り切る） |
| 戻る / 進む | あり | **なし** |
| 2 本指タップ | 戻る | なし（2 人目の指として描く） |

戻るを持たない理由は、同時に描いていると「**誰の 1 手を戻すのか**」が決められず、
他の子の線を消す事故になるため。モードへ入る時点で履歴も捨てる（持ち越すと同じ事故が起きる）。
拡大も等倍へ戻す（拡大したままだと隣の子の描く場所が画面外になる）。

## ツールバーの横スクロール

道具は増えていくが、**折り返すとキャンバスの高さを食う**（iPhone 縦では 3 段 244px になった）。
そこで折り返しをやめ、**横に流す**方式にした。

横スクロールの弱点は「画面外にボタンがあることに気づけない」こと。これは
**両端の送りボタン（＜ ＞）**で解く。送り先が無い側は出さないので、
矢印があること自体が「まだ先がある」という合図になる。

- 指はそのまま横スワイプ（`touch-action: pan-x`）
- マウスはドラッグでも流せる。**少しでも動いたらボタンの click は打ち消す**
  （ドラッグの終わりに道具が切り替わる事故を防ぐ。捕捉フェーズで止める必要がある）
- スクロールバーは出さない（子どもが摘まむには細く、高さも食う）
- 送りは 1 回で表示幅の 8 割。全部入れ替わると今どこにいるか分からなくなる
- 「完成！」は右端に貼り付けない（横に流すので画面外へ行ってしまう）。色と幅で目立たせる

## 下敷き（マス）のサブメニュー

「マス」ボタンを押すと **なし / 方眼 / ビーズ** から選ぶ（既定は なし）。
方眼もビーズも「マス目の上に描く」同じ系統なので、道具を増やさず 1 つのサブメニューにまとめた。
将来のドット絵モードもここへ足す（`src/core/grid.ts` の `GRID_MODES` に 1 件足すだけ）。

- マス目は **キャンバスには一切描かない**（紙と下敷きを包む入れ物に CSS で重ねるだけ）。
  保存データにも「完成！」の PNG にも入らず、ピンチ拡大には一緒に追従する
- ツールバーのボタンには **いま選んでいる下敷きの絵**を出す（開かなくても状態が分かる）
- どれを選んでいるかは作品ではなく人に属する設定なので `progress`（localStorage）に持つ
- `snap: true` の下敷き（ビーズ）だけがマス目に吸着し、太さもペン先も持たなくなる

## 塗りつぶし

囲んだ内側を塗る（走査線方式の flood fill）。線はアンチエイリアスで境界がぼけるため、
色一致だけで止めると **線の内側に白い輪が残る**（子どもの絵では必ず目につく）。
塗った範囲を 2px だけ外へ広げて線の下へ潜り込ませている。
ふでの最小幅が 10px なので、2px の食い込みで反対側へ漏れることはない。

## ヘッダー

WebPaint98 / WebNP2 と同じ「ページ外側だけモダンな Web ページ」の構成。
フッターは置かない（リンクが無く、バージョン表記だけのために縦を取ると描画面積が減るだけ）。
バージョンはヘッダー右端に出す。値は **git commit 時刻（JST）＋短縮ハッシュ**で、
WebNP2 / WebPaint98 と同じ方式（`tools/version.mjs` + `tools/compute-version.mjs`）。
ビルド時刻（壁時計）を使わないので、同じコミットからは何度ビルドしても同じ文字列になり、
画面の表示から動いているコミットを一意に辿れる。作業ツリーが汚れているときは `+` が付く。
git が使えない環境では `version unknown` に落とし、ビルドは止めない。

## 線の太さ

5 段階（3 / 6 / 10 / 26 / 60px。キャンバス実解像度 1748px 幅に対する値）。
細い側の 3 と 6 は、画面に収めて表示すると 1〜3px 相当にしかならない
**拡大して描き込むための段**で、等倍のまま使うものではない。既定は中央の 10。

パネルの丸は実寸をそのまま出さない（太い側は大きすぎ、細い側は差が見えない）。
平方根で圧縮して、どの段も隣との違いが分かる大きさにしている。

## ペン先（クレヨン / 色えんぴつ / Ｇペン / 筆 / 油絵）

「描く」パネルの上段でペン先を選ぶ（ツールバーは増やさない）。既定はクレヨン＝**太さ一定**で、
「触れば思った太さで出る」という Phase 0 の芯を壊さないため。Ｇペンと筆は
**大人がお手本を見せるとき**に効く道具として足した。

筆圧センサーが無い環境でも「Ｇペンっぽさ」は作れる。効く順に:

1. **速さ→太さ**（最重要）… 速く動かすと細く、ゆっくりだと太い。「シャッと抜ける」感触の正体
2. **入り抜き** … 描き始めと描き終わりを細くする。無いと線が「棒」に見える
3. **手ブレ補正** … 座標を指数平滑化する。子どもの手のブレを吸収する効果が大きい

実装上の要点:

- 描き終わりを細くするには「どこが終わりか」が要る。末尾（抜きに使う長さ）は
  **描かずに保持**し、`endStroke` でまとめて細らせながら描く
- ただし保持したままだと **線が指から遅れてついてくる**（保持長ぶん）。
  そこで末尾は専用の層（`Surface.overlay`）へ**仮のインク**として即座に描き、
  指を離した時点で本番（細らせたもの）をキャンバスへ描いて仮インクを消す。
  実測で遅れは 60px → 16px（キャンバス座標。表示上およそ 6px）まで縮んだ。
  残りは手ブレ補正の追従分で、これは補正の効果と表裏なので残す
- 手ブレ補正の分だけ描画点は指より後ろにいるので、`endStroke` で
  **離した位置まで線を伸ばす**（「線が指まで届かない」感じを消す）
- スタイラス（Apple Pencil 等）では `PointerEvent.pressure` を優先。ただしマウスは押下中つねに
  0.5 を返すので、**0.5 ちょうどはセンサー無し扱い**にして速さの計算に任せる
- 消しゴムは太さ一定のまま（消す量が変わると狙って消せない）
- 端の太さは 0 にせず下限を置く（0 にすると線が途切れて見える）

### 質感（色えんぴつ・油絵）

太さの計算とは別に、**描き方そのもの**を変える 3 系統を持つ（`NibDynamics.texture`）。

- `smooth` … 1 本の線を引く（クレヨン / Ｇペン / 筆）
- `pencil` … **薄い粒をばらまく**。1 回で塗り切らないので、同じ場所を重ねるほど濃くなる＝
  本物の色えんぴつと同じ手応えになる。粒は線の直交方向にばらつかせ、紙の目に見せる
- `oil` … **何本もの筋を並べて引く**。毛ごとに色を少し明るく／暗くして絵の具の盛りに見せる

油絵で踏んだ落とし穴: 毛の位置と濃さを **区間ごとに乱数で決めると筋が繋がらず、格子状の模様**
になる。ストロークの最初に毛並みを決めて固定する（`StrokeState.bristles`）。

色えんぴつと油絵は入り抜きを持たない（重ねて描く道具なので、端を細らせる意味がない）。
入り抜きが無い＝末尾を保持しないので、仮インクの層も使わず遅れも出ない。

## 履歴（上書き事故からの復旧）

共用タブレットで **他の子の絵に上から描いてしまう事故** への備え。方式を選ぶにあたって実測した
（1748×1181 の線画 1 枚）:

| 方式 | 1 枚あたり |
|---|---|
| 全面 PNG | 53〜186KB |
| WebP 可逆 | 323KB（線画では **PNG より大きい**。採用せず） |
| WebP 非可逆 q0.8 | 28KB（線がにじむので復元用には不可） |
| サムネイル（幅 360） | 4〜17KB |

ブラウザの割当は 3GB（測定環境）。**全面 PNG のスナップショットなら 1 作品 20 枚持っても 1〜4MB**
で、容量は制約にならないと判断した。

**undo を全部保存する案は採らない。** 容量ではなく使い勝手の問題で、(1) 逆差分の連鎖なので 1 つ壊れると
以降が全滅、(2) 数百件の細かい差分は子どもが選べる一覧にならない、(3) そもそも必要なのは 1 手単位ではなく
「その子が触る前の姿」。

**コマンド記録（描画操作のログ）も Phase 0 では採らない。** 容量は圧倒的に小さく任意地点へ戻せるが、
再現がブラシ実装に縛られる（仕様を変えると過去の絵が変わる）、途中 1 手の破損で以降がずれる、
画像取り込みやフィルタ（Phase 2 以降）が入ると破綻する。定石どおり
「キーフレーム画像＋間のコマンドログ」にするなら、ブラシ仕様が固まってから足す方が安全。
スナップショットは `reason` タグ付きなので、後からログを併用しても壊れない。

### 保持ルール（Time Machine 方式・`thinSnapshots`）

- 直近 10 件は無条件
- そこから 14 日ぶんは **1 日 1 件**（その日の最後の姿）
- さらに古いものは 8 週ぶんを **1 週 1 件**
- 上限 40 件

「直近 N 件」だけにしないのは、翌日に別の子が延々描いた時点で前日の姿が押し出され、
上書き事故の復旧に間に合わなくなるため。

### 撮るタイミング

- `open` … **作品をひらいた直後（描き始める前）**。これが上書き事故の戻し先になる。起動時の復元も含む
- `auto` … 描いている途中、3 分おき
- `revert` … 巻き戻す直前（巻き戻し自体をやり直せる。「戻したらもっとひどくなった」を作らない）

### UI（横スクロールのタイムライン）

作品カードの「前に戻す」→ 履歴 →「これに戻す」。

履歴は日付と時刻を数字で並べても、どれが「さっきの姿」なのか子どもには判断しづらい。
そこで **左が古く右が新しい 1 本の帯**にして、位置関係そのもので時間を見せる。

- 開いた瞬間は **右端（＝「今」のチップ）** にいて、指で左へスライドすると過去へ遡る
- 日付は帯の途中に区切りチップとして立て、カードには時刻だけを出す
- 各カードの下に軸線上のドットを置き、「並んでいる 1 本の時間」に見せる
- `scroll-snap-type: x proximity` で、雑にスワイプしてもカードが半端な位置で止まらない
- 「ひらいた とき」「戻す まえ」の一言を添える（上書き事故の戻し先が一目で分かる）

### 保存が消えないように

起動時に `navigator.storage.persist()` を要求する。Safari は使われていないサイトのデータを
一定期間で消すことがあり、「たまにしか開かない共用 iPad」がまさにその条件に当たる。

## 進捗（道具箱）の保存先

絵は作品ストア（IndexedDB）、**増えた道具と描いた量は localStorage**（`src/core/progress.ts`）。
道具箱は作品ではなく *使う人* に属するので保存先を分けている。ここを分けずに作品側へ入れると、
リロードで道具箱だけ巻き戻って宝箱がもう一度出るという事故になる（実装中に一度踏んだ）。
壊れた保存データを読んでも初期道具は必ず揃うようにしてある。

Phase 1 で「じぶんのマーク」を入れる際は、この進捗をマーク単位に分ける拡張点になる。

## 宝箱（道具の解放）は現在 OFF

道具の種類が増えたので、まずは **最初から全部触れる状態**で作り込みと検証を進める段階にある
（`CHEST_ENABLED = false`）。解放の仕組みは残してあり、`true` に戻すだけで元に戻る。
企画書の「育つ UI」は宝箱が本命なので、道具の整理が済んだら戻す前提。

## Phase 0 の範囲について

作品カタログ・履歴・ペン先など、仕様書の Phase 0 を超えた機能が入っている。方針として
**作れるものは先に作り、検証時に絞る**（下記「おためしモード」）を採る。
プロトの検証対象は「説明ゼロで 1 枚描き切れるか」なので、
子どもに渡すときは道具を初期 5 個相当まで減らした状態で観察する。

## アイコン

名称確定（2026-08-30）に伴い「いろはモミジ（7 裂＝いろはにほへと）×虹の 7 色・クレヨン風」を採用。

- マスターは `assets/icon-master.png`（不透明。クリーム色の角丸板の上に葉が乗った状態）
- 配布用は `public/icon/` に生成する。**抜くのは板ごとで、残すのは葉だけ**。
  favicon や UI に置いたとき下地から浮かないようにするため
- 背景は「白い外側 + クリームの角丸板」の 2 層なので、外周から繋がる背景を 1 色ずつ剥がす処理を
  繰り返している（1 層だけ抜くと板が残る）。縁のにじみからは背景成分を引く
  （残すと暗い下地でクリーム色のフチが光る）
- iOS のホーム画面アイコン（`apple-touch-icon.png`）と Android の maskable だけは
  **透明が黒く落ちる／切り取られる**ため、板の色を敷いた不透明版を別に作る
- 16〜64px は縮小すると輪郭とクレヨンの黒が薄まって眠くなるので、
  アンシャープ＋彩度・コントラストを軽く上げてから書き出している

生成スクリプトは使い捨て（`assets/icon-master.png` を差し替えたときだけ再実行する）。
手順は本節の記述で再現できる。
