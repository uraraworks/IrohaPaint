# マンガ（コマ割り・トーン）

1 枚の紙にコマの枠を敷き、コマの中に絵を描いてマンガの原稿を作る。
2026-09-25 に画面の形を決めた。
土台はレイヤー（かさね）とパラパラで整った `pages[]` / 版ストア（`docs/page-versions.md`）。

## 調べて分かったこと

- **マンガは紙の種類ではなく「枠を敷く」機能にする**。はがき縦に 4 コマ、はがき横に 2 コマも
  自然に成り立つので、コマ割りは紙の大きさから切り離す。B4 原稿は「大きい紙が 1 つ増える」だけ
- `CANVAS_SIZES` の `manga-b4`（1748x2476）は定義済みで、一覧の「あたらしく かく」からは外してある。
  紙の縦横比は `--paper-w` / `--paper-h` で CSS に流していて、はがき縦（1181x1748）で縦長は
  一通り動いている。B4 は比率 1.42 で、はがき縦の 1.48 とほぼ同じなので、**表示の作り直しは
  たぶん要らない**（着手時に実機で確かめるだけ）。控え 1 枚は 1748x2476x4 ≒ 17MB で、
  はがきの 2 倍。かさねは控えを 1 枚しか持たないので問題にならない
- ぬりつぶしは **合成結果で境界を判定**して、書き込みだけ今のかさねに回す作り
  （`floodFill` の `out`）。枠の線を合成結果に含めれば、**コマの中を 1 回押すだけで塗れる**。
  トーンもここに乗る
- 書き出しと保存の絵は `Surface.composite()` が 1 か所で作っている。枠を絵に焼くのはここだけでよい
- パラパラの「コマ」と言葉がぶつかる。マンガの枠は画面では **「わく」**、トーンは **「もよう」** と呼ぶ（2026-09-25 本人合意）

## 決めたこと：画面

- 一覧の「あたらしく かく」に 3 つ目の **「マンガ」**（B4 縦）を足す。ボタンは 1 タップで作れる今の作法のまま
- **「わく」は「マス」のサブメニューに同居させる**（2026-09-25 本人判断）。マスは焼かない下敷き、わくは焼く線で
  性格は違うが、子どもにとってはどちらも「紙に敷くもの」で、ボタンを増やさない方を取った。
  サブメニューの中で「マス」の並び（なし／方眼／ビーズ／ドット／写真）の後ろに **「わく」の段** を置き、
  コマ割りのお手本から選ぶ。最初のお手本は 3 つ：
  - なし／4 こま（縦一列＝4 段 1 列。4 コマまんが 1 本）／2 だん（2+2）
  - B4 で「4 こま 2 れつ」（4 段 2 列＝1 ページ 8 コマ。原稿用紙の定番）が欲しくなったら足す。
    木のデータなのでお手本を 1 つ増やすだけ
  - お手本は紙の大きさによらず、割合で敷く（はがきでも B4 でも同じ表が効く）
  - マス（下敷き）とわく（枠）は **別々に選べる**。方眼を敷いたまま 4 こまにできる。
    サブメニューの中で 2 つの段になっていて、それぞれに「なし」がある
- **わくの行はパネルの一番下**（写真の帯より後ろ）に置く。写真の帯はすぐ上の「写真」ボタンの
  下に出てほしいので、その間には割り込ませない（2026-09-26）
- **「なし」は「わくなし」と表示する**（2026-09-26）。マスの行にも「なし」があるので、
  同じ名前のボタンが 2 つ並ぶとどちらを押したか分からなくなるため
- **マンガの紙(manga-b4)は 4 こまのわく付きで始める**（2026-09-26）。白紙だとはがき縦と
  ほぼ同じ見た目になり、「マンガ」を押した甲斐がない。いらなければ「マス」で「わくなし」を選べる
- ツールバーの「マス」ボタンは、マスの下敷きが無くてもわくがあれば点灯する。アイコンは
  マスの下敷きがあればそちらを、無くてわくだけあればそのお手本の絵を出す（2026-09-26）
- **わくの線は絵に焼き込む**（マスと違い、保存した絵・書き出し・サムネイルに出る）。
  ただし **かさねの画素ではなく、別の層**として持つ：
  - 消しゴムで枠が消えない（子どもがコマの縁を消しても枠は残る）
  - 後からお手本を変えられる（塗った色や線はそのまま、枠だけ引き直る）
  - ぬりつぶしの境界になる（コマの中を 1 回押すと、そのコマだけ塗れる）
- 枠の外（余白）にも描ける。はみ出しは止めない（止めると「描いたのに出ない」が起きる。
  かさねの「描いたら出てくる」と同じ考え）
- **「わく」は戻る（undo）の対象にしない**。押し直せば済むし、履歴に混ぜると
  「戻る」で枠が消えて子どもが驚く。控え（前に戻す）には作品ごと残る
- パラパラの作品にも「わく」は敷ける（コマごとに持つ。制限しない。使い道は子どもが決める）

## 決めたこと：トーン（実装済み）

- 画面では **「もよう」**。置き場所は仕様書では「いろ」のパネルと書いたが、実装では
  **「塗る」のパネル**（かこみ／しかく／まる の行）に **2 行目** として置いた。もようは
  塗るときにしか効かないので、「いろ」に置くと「もようを選んでペンで描いても何も起きない」で
  子どもが戸惑う。「いま選んでいる色がもようの色」は仕様どおり（黒だけに縛らない）
- もようは **かこみ・しかく・まる の 3 つ全部**で効く。ペン・消しゴムには効かない
  （道具は増えない）
- マス目に吸着するモード（ビーズ・ドット絵、`this.cellGrid !== null`）ではもようは効かず、
  今までどおりのべた塗り。その間は「塗る」パネルのもようの行を薄く（`is-dim`）するが、
  押せなくはしない（選んだもようは覚えておく）
- もようの隙間は **透明**。紙の上ならトーン、色の上に重ねれば色つきの点々になる
- もようは **保存しない**（起動時は常に「もようなし」）。戻る（undo）は今までどおり
  塗った結果（色 or もよう込みの画素）に効く
- 実装：`src/core/pattern.ts` に `PatternId`（solid/dots-light/dots/dots-dark/stripes/mesh）と
  お手本の表を持つ。`patternTile(id, color)` が 24x24 の `HTMLCanvasElement`（もようの
  タイル絵、solid は null）を (id, color) でキャッシュして返す。`Surface.fill` /
  `previewShape` / `fillShape` に `tile: CanvasImageSource | null` を足し、
  `ctx.createPattern(tile, "repeat")` で塗る。**パターンの原点はキャンバスの (0,0)**
  （patch も this.ctx/this.overlayCtx もキャンバスと同じ大きさで変換なし）なので、
  隣り合う領域を別々に塗っても点の並びがずれず繋がる。下見（previewShape）も
  出来上がりと同じ見た目でもようを出す
- タイルは 24x24 の正方形、端で継ぎ目が出ないように描く：
  - 網点（うすい/てんてん/こい）：4 隅 (0,0)(24,0)(0,24)(24,24) と中心 (12,12) に円 →
    45° に並んだ網点（間隔 約17px）。半径 うすい3 / てんてん4.5 / こい6.5
  - しましま：x+y=c の斜め線を c=0,24,48 の 3 本、線幅6
  - あみあみ：しましまの線（線幅3）＋逆向き x−y=c の線（c=−24,0,24、線幅3）
  - B4 をタブレットで見ると紙は約 1/3 に縮む。点の間隔が画面で 5〜6px あれば点として
    見える。モアレは実機で見て詰める（未実施）

### 分かっている弱点

- もようを塗った所を後から別の色で「かこみ」塗りし直すと、もようの隙間（透明）だけが
  塗られて元の点が残ってしまう（`floodFill` は色の一致で範囲を決めるため、もようの
  隙間はまだら状の「境界」になる）。消しゴムか「戻る」で消す。気になると言われたら考える

## 後回しにするもの

- **ゆびで きる**：コマを指でなぞって 2 つに割る。お手本で足りなくなってから。
  データを「割った木」で持っておけば（下記）、お手本＝出来合いの木なので後から足せる
- **ふきだし**：手で描けばよい。欲しくなったら「まる」の形に「白で塗って黒で縁取る」を足す
- **複数ページ**：`pages[]` は既にあるが、今は `animation` の真偽でパラパラのコマとして使っている。
  マンガのページめくりを入れるときは `animation: boolean` を `kind: "flipbook" | "book"` に
  育てる。**最初は 1 枚**（4 コマまんが、1 ページの原稿）で始める
- **文字**：キーボードは使わない。手で書く
- 断ち切り・基本枠の目安線：大人向け。求められたら「マス」の下敷きとして足す（焼かない）

## データ

- `PageData.frame?: FrameData` … 無ければ枠なし（今までの作品はすべて無し）
- `FrameData` は **割った木**で持つ（`src/core/frame.ts`）。お手本もこの木の出来合い：
  ```
  FrameNode =
    | { kind: "leaf" }
    | { kind: "split"; axis: "x" | "y"; sizes: number[] /* 比 */; children: FrameNode[] }
  FrameData = { margin; gapRow; gapCol; lineWidth; root }  // どれも紙の短辺に対する割合
  ```
  - 1 つの split で **n 個に分ける**。間を先に引いてから比で分けるので、等比ならぴったり等分になる。
    最初は「at の位置で 2 つに割る」入れ子にしたが、割るたびに間を引くせいで 4 こまの高さが
    下ほど低くなった（2026-09-26 に直した）
  - 木にしておく理由：「ゆびで きる」は葉を 2 個分けの split に差し替える（か、親の split に子を
    1 つ挿す）だけで届く。お手本の id だけ持つと、後で切れるようにしたとき形が変わる
  - `framePanels()` はコマをマンガの読み順（上の段から、同じ段は右から左）で返す
- `frame` は **版（`PageVersion`）の側**に持つ。わくを変えると絵を焼き直して新しい版になるので、
  絵と同じ単位で持つのが筋。読み込みで `isFrameData()` に通らない値は捨てる
- 線の太さ・余白・間隔は割合で持ち、描くときに紙の大きさへ換算する
  （段と段の間 `gapRow` を、左右のコマの間 `gapCol` より広く取る。これがマンガの読み順の目印）
- `splitWork` / `joinWork` は項目を並べているので、`frame` を必ず通す（パラパラのときの教訓）
- 控え（`WorkSnapshot`）は `PageData` ごと持つので、枠も一緒に戻る

## 描画と保存

- 枠は `canvas.frame-layer` を **仮インク（overlay）の直後**（＝全部のかさねより上）に置く
  （DOM 順で合成。JS で毎フレーム合成しない、の原則どおり）。`pointer-events: none`。
  `Surface.restack()` が「アクティブより上のかさね」を overlay の直前に差し込むため、
  overlay の後ろに置けば常にかさねより上へ来る
- `Surface` に **「最後に重ねる 1 枚」**（overprint）を渡せるようにし、`composite()` の末尾で描く。
  これで保存の絵・サムネイル・書き出し・ぬりつぶしの境界判定が、全部同じ枠を見る
- **`flattenVisibleLayers()` だけは枠を混ぜない合成（`composite(false)`）を使う**。あちらは
  かさね本体を合成結果で焼き直す処理なので、枠を混ぜると枠の線がかさねの画素になり、
  消しゴムで消えるようになってしまい、お手本を変えて保存するたびに古い線が画素として
  二重に残ってしまう
- パラパラの「＋」（コマを増やす）は **今のコマのわくを引き継ぐ**。焼き直し（`syncFrameLayer`）は
  呼ばない: いま画面に出ている frame-layer/overprint がそのまま新しいコマの白紙にも乗る形で、
  コマ割りの中で動きを描くのが自然なため（コマごとに敷き直させない）
- 再生（「見る」）中は frame-layer を隠す（`.frame-layer.is-playing`）。再生は各コマの
  焼き込み済みの絵（わく込み）を出すので、今のコマのわくが上に重なると他のコマとずれて見える
- お手本を変えたら `scheduleSave()` を通す（通さないと保存されない）。画素は変わらないが
  `frame` が変わるので `dirty` を立てる。**今のコマだけ**焼き直す作りはそのまま。
  `save()` の `bake()` は base を `PageData` 相当（`frame` 込み）で受け、`frame` を
  素通りさせる（通さないと、自動保存のたびに枠が消えてしまう）
- 紙の質感（乗算）は枠の上に乗るが、黒い線には効かないので見た目は変わらない
